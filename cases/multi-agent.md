# 多 Agent 协作：任务编排与执行治理

本案例讨论任务路由、确定性处理与模型推理解耦、独立复核，以及执行可观测性与检查点管理。内容来自个人工程的历史记录与交付文件核验；AI辅助实现与复盘，不将全部方案或代码归为个人独立完成。

更新与核验日期：2026-10-22。

## 项目定位

这个项目探索如何把不同模型与本地程序组织成可追踪的工作流程。平台保存任务、分工、模型输出、检查点和交付状态；模型负责生成或评审；本地程序处理确定性转换；用户决定关键交付取舍。

对运营工作的价值是让“谁处理了什么、结果到哪一步、哪里还未验收”可以查清。多模型调用本身不代表质量更高，需要通过具体问题与修改证明协作价值。

## 回放一条实际数据制作任务

2026-10-22核验时选取2026年8月25日“构建150条产品到用户画像课堂训练样本”任务。它与另一个审计任务有关联，但两者是不同任务，不能合并宣称整批数据已经独立审核通过。

任务链路为：提出150条课堂样本要求 → Codex整理来源与输出结构 → 智谱转换 → 发现格式、时延与证据问题 → 调整中间传输及本地还原 → 交付JSONL → 保留待复核状态。

| 阶段 | 记录中的动作 | 2026-10-22核验时能证明什么 |
|---|---|---|
| 需求与来源 | 整理来源清单，要求画像及文案能回链证据 | 有任务说明、来源文件路径和检查点；来源许可2026-10-22核验时未重审 |
| 结构试运行 | 智谱生成结构化候选 | 有8条economy响应记录，模型字段为glm-5.2；这是账本所存元数据，不是2026-10-22核验时供应商核验 |
| 需求调整 | 追加面向人群的文案字段，要求保留最终嵌套结构 | 有Codex回填的用户决定记录；它不是用户原始对话的独立副本 |
| 异常调整 | 普通批次出现超时，尝试紧凑字段传输，再用程序还原结构 | 检查点记录了调整；未据此计算提速比例 |
| 交付 | 输出JSONL与表格 | 2026-10-22核验时实际读取原版JSONL：150条均具备Q、Thinking、嵌套A及非空seeding_copy |
| 质量状态 | 未校验内容保留标记 | 原版JSONL的review_status为140条needs_human_review、10条pass；字段标签不是独立质量结论 |

这里的Thinking是样本要求的简短依据字段，并不代表取得模型隐藏推理。原版交付结构已核对，但2026-10-22核验时没有逐条核验商品事实、画像推断与文案质量。

## 独立复核具体纠正了什么

关联任务“审计课堂产品用户画像训练数据方案”中，主责初稿在未读取样本的情况下写了“暂定不通过”。账本中标记为Claude的复核意见指出：缺少材料只能说明尚无法审计，不能说明已检查并发现不合格。随后主责版本改为“无法验收，待补证复核”，并将新增规则标为建议。

这是可以逐段对照的协作价值：纠正了结论强度与证据不匹配的问题。另一条复核指出，应区分用户需求门槛与商品实际满足依据，卖点必须回链到后者。

但这次复核审的是方案文本，不是150条最终数据。关联任务状态仍为awaiting_confirmation，响应中的实际model字段为空。因而公开版本最多表述为“账本记录了一次跨角色复核及修订”，待补足模型身份依据后再使用具体供应商身份作为证明；不能写成“Claude验收通过150条数据”。

## 为什么交付和验收必须分开

生成任务的顶层状态为delivered，而outcome.status仍为pending，原版数据多数也待复核。历史完成回填提到6条补齐样本需人工复核，2026-10-22核验时发现最终字段实际有140条待复核；这两种统计范围不能混用。

现有证据证明完成了结构化交付，不证明150条达到训练质量。这个差异暴露了流程改进点：状态应分别表达“已生成、结构通过、语义复核、人工确认、可用于训练”，否则一个完成标签容易掩盖未完成工作。此分层是2026-10-22核验时提出的改进建议，尚未实施。

## 异常恢复的补充证据

另一个长期任务保存了2026年9月10日入口故障演练检查点及报告：平台离线时明确返回connected=false，恢复前后原任务消息数保持11，路由保持D。报告记录服务恢复成功，避免把离线登记伪装成已同步。

2026-10-22核验时交叉读取到任务检查点和同日演练报告，两者相符；没有重新停止服务，也未重新执行测试。它适合作为历史故障处理案例，不证明当前服务稳定性。该长期任务仍为understood，也不能将局部演练成功等同于全部升级完成。

## 已验证的成果与限制

已核验的成果是：存在模型转换记录、可追踪的需求变更、一个方案复核修订链、150条结构完整的原版交付数据，以及历史恢复演练记录。尚未证明的是整批语义质量、全局节省成本、稳定提速及当前系统可靠性。

这项实践可以支撑流程拆解、异常跟踪和质量状态管理能力。它不直接证明真实供应商管理或线下跨团队沟通能力。
