# 人机交流中的意图对齐与推进范围管理

这套日常交流规则形成于个人与AI的实际协作，以Codex为首个试用环境。它围绕信息理解、双向提问、范围确认和反馈修正，帮助用户意图、AI理解与实际行动保持一致。高效、准确的信息沟通是首要目标，表达训练是次要目标。

它是一组可以阅读、复制和调整的行为指令，不是技术权限系统，也不能保证模型每次都正确执行。

## 从哪些问题开始

形成规则时，用户关注的不只是回答是否足够详细，还包括信息是否容易提取、理解是否准确、下一步是否符合预期，以及反馈后能否保留仍然有效的决定。

以下精选原话来自同一位用户，采用匿名叙述。引用之外的说明是整理与归纳。

### 信息多，不等于容易理解

> 你的信息量很多但我自己提取信息和总结有点费劲

对应的规则要求结论前置，区分用户原意、AI判断、修正与补充，按需使用短段落或列表。重点是减少读者重新整理信息的成本，不是把所有回答都压成短句。

### 用场景组织交流方式

> 我更希望的是你通过日常最高频的使用场景的分类来做一套通用一点的交流规则

由此形成七类场景：开始新工作、了解与学习、探索与构思、比较与决策、制作与执行、反馈与迭代、梳理困惑。AI根据上下文识别场景，允许重叠，用户无需先分类或填写模板。

### 理解是否正确，由用户判断

> 理解的判断尺度是在我这里，因为你要理解的是我输入的个人信息。

讨论中曾出现“AI总结后自行判断理解明确即可继续”的建议。用户提出异议后，规则明确要求展示理解、拟处理方式、范围和停点，在尚未授权的实质处理前等待确认；已获许可的范围内则不逐个步骤重复询问。

### 问题由双方一起澄清

> “我问你答”加上“你问我答”，这两个结合起来，才是我们沟通最本质、也最有效的方式

规则要求AI指出缺失的维度、具体疑点及其对判断的影响，并优先询问少量影响方向的问题。已有上下文应被利用，补充信息也不自动等于执行授权。

### 下一步需要说清楚

> 你每次总结之后，需要跟我说下一步是什么、你预计的下一步是什么，这样我就不用问了。

AI应说明下一步、理由及是否需要确认，让用户可以调整或否决。建议不能自行变成授权，任务完成后也不应为了继续交流而增加工作。

### 表达训练服从沟通效率

> 权重最高的核心始终在于如何进行高效的信息沟通

表达训练通过清晰总结和针对性提问自然发生，默认不评分、不强迫重写。出现问题时先分析原因，再决定是否修改规则，不因一次失误就增加长期条款。

## 规则怎样工作

用户表达 → AI整理理解 → 必要时双向提问 → 明确范围与停点 → 用户确认 → 范围内推进 → 反馈与修正。

这不是每轮都必须完整重复的固定模板。简单确认只概括新增决定，场景分类只有有助于对齐时才展示。已获许可的工作应继续完成；目标、范围或重要取舍变化时再交回确认。

## 预期价值与代价

| 机制 | 预期作用 | 需要观察的代价 |
|---|---|---|
| 展示理解与范围 | 尽早发现方向偏差 | 总结重复、阅读负担 |
| 用户确认阶段 | 减少未经授权的范围扩大 | 确认过细，推进变慢 |
| 按维度提问 | 让补充信息更有针对性 | 问题过多，变成长问卷 |
| 区分原意与新增判断 | 减少混淆与重新整理 | 表达机械、格式过重 |
| 明确下一步 | 减少反复询问进度 | 引入不必要的新任务 |
| 定期审议 | 发现过时或不适用的规则 | 维护本身需要时间 |

这些是机制设计的预期，不是已测得的效率提升。项目不主张所有机制原创，也不宣称适合所有使用者。

## 已知实践与证据边界

完整规则已用于个人Codex环境，本次发布准备时核对了规则正文。交接记录记载曾进行一次30天审议触发；此次没有重新检查定期任务当前状态。审议提出的“确认可能过多”和“原始主线推进偏慢”仍待用户评价，不作为已确认缺陷或已解决问题宣传。

目前没有对照实验、效率百分比或跨模型验证。AI自检不代表能够读取或监控全部对话，也不能替代实际反馈。

## 如何试用和维护

1. 先阅读完整规则，在一个常用AI环境中试用，并遵循该环境的指令优先级和工具权限。
2. 观察是否更少重复解释、更容易抓住重点，以及无必要确认是否减少、原目标是否持续推进。
3. 发现问题时先区分执行偏差、规则不合适、理解偏差和能力限制；不要立即堆叠新规则。
4. 实质修改前展示修改对照、预期改善与代价，由使用者确认，保留旧版并验证；必要时回退。

规则原文中的“依靠已设置的定期任务触发”描述原作者环境。复制规则不会创建定时提醒，其他使用者需要自行设置；它也不会自动收集其他对话。跨AI迁移需要适配上下文、工具与权限条件，目前未验证其他模型的适用效果。
